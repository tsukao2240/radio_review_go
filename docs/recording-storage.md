# 録音の保存とダウンロード後の削除

- 保存ダイアログで保存を確定し、端末ファイルへの書き込み・クローズに成功した後、`POST /recording/download/complete` でDBへ保存済みを記録してから音声ファイルとRedisの一覧情報を削除する。GETの送信完了だけでは削除しない。
- Rangeによる部分取得、HEAD、再生、送信失敗、DB記録失敗の場合は削除しない。
- File System Access APIの保存ダイアログを利用する。キャンセル・書き込み失敗・途中切断では録音を保持する。非対応ブラウザでは通常ダウンロードを行うが、自動削除せず手動削除とする。全量送信時に発行する短期の受領証とCSRFトークン、所有者確認が揃った場合のみ削除APIを受け付ける。
- 録音予約のDB行はcompletedのまま保持し、recording_metadataにdownloaded状態とdownloaded_atを記録する。file_pathは空にする。auto_recording_keyの一意制約も保持し、再起動・Redis消失後も同じ放送を再録音しない。
- 音声ファイルが残ったまま削除処理が中断した場合は、既存の孤児ファイル清掃によって回収する。
- 導入前にダウンロードしたかどうかは判定できないため、既存音声を一括削除しない。

## 永続化

自動録音の確定情報と重複防止はMySQLに保存する。Redisは一覧・進捗・認証キャッシュであり、お気に入り録音の情報はDBから復旧する。

Dockerの通常のstop/start/restartではボリュームは削除されない。MySQLの名前付きボリュームとstorageマウントを維持する。ボリューム削除やDB初期化は別の操作であり、実施しない。
